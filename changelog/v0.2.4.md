# v0.2.4

## 2026-11-22

### Start of version 0.2.4

#### Added
- **Work for this version has started:** the app reports v0.2.4. The entries below are added as each change lands.
- **GitHub connection card on the Agent page.** It says what to set on the GitHub webhook (payload URL, content type, secret, events), has a **Check the receiver** button that signs a test message with the server's secret, and lists the latest deliveries with what RepoLens did with each, including why one was refused (for example a secret that differs). GitHub's ping is answered and recorded. New table `webhook_deliveries` (migration 0040); only the event, action, repository name and a one line note are kept, 300 rows for 30 days.
- **Commands in a pull request comment.** `/repolens review` reviews the pull request now and `/repolens ask <question>` answers a question from the repository's index, each leaving a draft in the Inbox. Only an owner, a member or a collaborator can use them, never a bot; they obey the pull request rule's switch, daily limit, the pause and the token budget. A question has **Answer again**. Add the **Issue comments** event to the GitHub webhook to use them.

- **Inventory tab.** Knowledge has an **Inventory** tab with the environment variables, commands and database tables of one repository or all of them, a filter, a **Copy list** button and the file and line of each item, without asking in chat. `GET /api/inventory`.

#### Changed
- **Suggested fixes tell you about GitHub access before and after approving.** A line under a pending fix says whether the saved token can push to the repository (found without writing anything). A token that can only read is refused before anything is changed, with what to grant. A refusal names the step and the permission (Contents or Pull requests: Read and write); if a step fails after the branch was made the branch is deleted so nothing is left on GitHub; and a failed fix has **Try again**. A checklist for the first real run is in `docs/operations.md`.

#### Upgrade notes
- Run the migration (`alembic upgrade head`, 0040). To use the commands, tick **Issue comments** on the repository's GitHub webhook.
