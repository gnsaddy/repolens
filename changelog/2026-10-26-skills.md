# Skills: guidance the model follows, approved by an admin

### Added
- **Settings → Skills**: members submit a skill (or upload a `SKILL.md`), admins approve, reject, turn off, edit or delete; an admin's own skills are active at once. Private to the workspace. Table `skills` (migration 0024), policy actions `skill.submit` (member) and `skill.review` (admin), `GET/POST /api/skills`, `PATCH/DELETE /api/skills/{id}`, `POST /api/skills/{id}/review`.
- **Used everywhere**: the best one or two approved matching skills are added to the prompt in the Ask chat, the Knowledge page, the DeepMind Wiki and investigations (`services/skills.py`); answers end with "Guidance applied: …" and the API returns `skills`. Matching is by words in the skill's name and "when to apply" line, optionally limited to kinds of task and a repository; "always" skills apply to every matching task.
- Safety: guidance sits in a marked block that states it cannot override the untrusted-source, citation and secret rules; secrets are masked on save; pending, rejected and disabled skills are never used; size caps (8,000 characters, 50 per workspace, 3,000 characters per prompt). Saved answers are keyed on the guidance used, so a new or changed skill is never answered from stale memory.
- The built-in guidance (walkthrough, build from conventions, debugging) is listed read only.
