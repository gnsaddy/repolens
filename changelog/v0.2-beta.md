# v0.2-beta

## 2026-10-27

### Graph: see how repositories fit together

#### Added
- A new **Graph** entry in the sidebar. Pick two or more repositories and RepoLens draws the code that connects them: the classes, functions and files on both ends of each link, each repository in its own area, with links across repositories as amber dashed bridges. Click a node to see where it is and the proof. The strongest proof is an **import**: when one repository imports a package another provides and uses it (`from fastapi import APIRouter, Depends`), the function that uses it is linked to the class or function defined in the other repository, found by following the package's re-exports, and the import line is shown. It also finds **calls over HTTP** (a URL in one repository that matches a route another serves, such as a payments service and the user service handler) and calls the code states. Documents never appear in it. A smaller repository map shows one arrow per pair; click an arrow to focus the code graph on it.
- Calls matched by a name alone are hidden by default and labelled uncertain, because unrelated projects share names (fastapi and repolens share over a thousand). A checkbox shows them.
- Graph, what breaks if I change this: click a class, function or file and see what in other repositories depends on it, with the proof, the two people who change those places most, and the callers one step further in. Repositories you cannot open are counted, not named.
- Graph, public surface: pick a repository and see what other repositories use from it, most used first, and which names its Python package exports that no repository here uses.
- Graph, what changed: dependencies between repositories that appeared or went away in the last 7 days, each with its proof. They are worked out again after each index (a minute later, in the background), so a new dependency is noticed even when nobody has the page open. What already existed when tracking began is not reported as new.
- Graph, coverage: a note under the graph lists the languages a finder cannot read yet, so an empty graph is not mistaken for "no dependencies".
- Graph, Ask: a question box on the Graph page, answered only from the repositories you picked (their code and documents) and from the dependency analysis: how they fit together, the proof lines that match the question, what changes together, and what depends on a selected class or function. Suggested questions come from the links found; "Explain this link" and "Explain what depends on this" ask without typing. Sources are numbered, analysis is marked, a cited source can be shown in the graph, invented names are flagged, a failed model call is reported, and a saved answer is not reused after the dependencies change. New policy action `group.ask` (viewers may ask).
- Graph, Ask now prefers code and the dependency analysis: documents are searched only when the question asks for them, and translated copies of documents (a locale folder under docs, such as `docs/de/`) are left out unless the question is written in another language. Before, a question about fastapi quoted its Hindi and Chinese tutorial pages.
- Dependencies are stored (`repo_links`, `link_states`, migration 0028) instead of being searched for each time the page opens, behind a detector interface; adding a new kind of link means adding one detector. New settings `REPOLENS_AUTO_LINK_REFRESH` (true) and `REPOLENS_AUTO_LINK_DELAY_S` (60). New metrics `repolens_repo_links` and `repolens_repo_links_new_total`.
- A heat map over the same picture: colour repositories by commits, lines changed, fix commits or documentation that may be out of date, plus a list of repositories that change together (a shared ticket key in commit messages, or the same person changing both on the same day).
- **Save as a system**: name a selection of repositories and keep it. Systems are shared with the workspace and show who saved them. Members can save; the author or an admin can change or delete. Up to 15 repositories per system and 50 systems per workspace.
- **Create knowledge for these repositories**: one click writes an overview of a system from those facts only, signed with the name of whoever asked and shared with the workspace. It shows the token estimate first, flags names that are not in the facts, reports a failed model call instead of saving anything, and without a model stores a labelled list of the facts.
- API: `GET/POST /api/groups`, `PUT/DELETE /api/groups/{id}`, `GET /api/groups/analysis`, `GET /api/groups/{id}/analysis`, `GET /api/groups/{id}/overviews`, `POST /api/groups/{id}/overview`, `GET /api/groups/code-graph`.

#### Changed
- Deleting a repository removes it from its systems (a system left empty is removed) and deletes overviews written from it.

#### Security
- A repository you cannot access is counted but never named in a system, is left out of its picture, and an overview built from it is hidden from you (checked on every read). The overview call is rate limited with the other model-backed calls.

#### Upgrade notes
- Run the migrations (`alembic upgrade head`, revision 0028). Nothing to re-index; the first look at the Graph page works the dependencies out, and that moment is where "what changed" starts. An arrow appears only when an index saw the other repository's code, so index a repository after the ones it uses; the daily re-index also repairs this.

### Saved questions check themselves, and RepoLens watches itself

#### Added
- After an index finishes and the code or documents actually changed, the workspace's saved questions run by themselves (a free retrieval run, no model). Several repositories finishing together give one run, two minutes after the last stops indexing. The Quality page says "ran by itself after indexing", and the server log warns when questions that used to pass now fail. An index that found nothing new, or a workspace with no saved questions, starts nothing. Turn it off with `REPOLENS_AUTO_QUALITY_CHECKS=false`; change the wait with `REPOLENS_AUTO_QUALITY_DELAY_S`.
- Insights → RepoLens health (admins): every background job (daily re-index, old-record clean-up, connected sources, stuck investigations, server readings, unused clones) as ok, waiting, late or failing with its last run and last error; repositories by status; the last saved-question result; and a plain-language list of what needs attention. Also `GET /api/metrics/health`.
- New `/metrics` series for dashboards and alerts: index runs, duration and retries; answers by mode and whether they came from memory, with their duration; model tokens (this counter existed but was never filled in); saved-question runs and the latest pass ratio; repositories by status; and, per background loop, when it last finished and how often it raised. Alert examples are in `docs/operations.md`.

#### Changed
- `golden_runs` gains a `trigger` column (`manual` or `reindex`).

#### Fixed
- A background loop that never started, or stopped, was invisible: the old-record sweeper once never ran and nothing showed it. Every loop now registers up front, so a loop that does not run shows as late.

#### Upgrade notes
- Run the migrations (`alembic upgrade head`, revision 0026). Nothing to re-index. Automatic runs are visible to admins only, like any run whose files were found without a person's access limits.

### Big repositories get time to read their history

#### Fixed
- OpenSSL failed to index with "git log timed out". Reading history uses `git log --numstat`, and in a blob-less clone git downloads the files each commit changed while it runs, so a big repository needs far longer than the 120 seconds every git call was given. Reading the history now gets `REPOLENS_GIT_HISTORY_TIMEOUT` (900 seconds by default); other git calls keep 120. Indexing a big repository is still limited by the network, not by CPU or memory.

#### Upgrade notes
- None. The next index of a repository that failed this way, or the daily check, picks it up.

### The combined graph shows every repository, not just the biggest

#### Fixed
- Choosing "All sources" in the graph showed 116 nodes of one repository and only 4 of another, although the second showed about 150 on its own. The server took the 120 most-connected nodes across everything at once, so a more connected repository crowded the rest out. With several repositories, each now gets its own share of the nodes and the total grows with their number (a share of 120 each, at most 400 in all); a smaller repository that does not fill its share leaves the room to the most-connected of the others. One repository behaves as before: its 120 most-connected nodes.

#### Upgrade notes
- None. The nodes are chosen when the graph is requested; there is nothing to re-index.

### The graph shows one world per repository

#### Changed
- With more than one repository, the graph gives each its own labelled region (name and node count). Repositories that are connected are drawn nearer to each other and unrelated ones apart, and a link that crosses from one repository into another is an amber dashed **bridge** you can hover to read. Before, every repository was pulled into one blob around the centre, so it looked like a single repository.
- Fit to screen leaves room for the names. A single repository looks as before.

#### Upgrade notes
- None. The graph is laid out in the browser; there is nothing to re-index.

### Failed indexes try again, changed repositories are re-indexed daily, and failures say why

#### Added
- **Automatic retry.** When an index fails with something that can pass by itself (a timeout, a dropped connection), RepoLens tries again after 1 minute and again after 5 (`REPOLENS_INDEX_RETRY_DELAYS`, in seconds; empty turns it off). A wrong path, address, branch or password is not retried. The retry only runs if the repository is still in the error state.
- **Daily re-index of what changed.** Once a day (`REPOLENS_AUTO_REINDEX_HOURS`, 24; 0 turns it off) each repository is checked cheaply (`git ls-remote` for a clone, the branch head for a local path), and only those that changed, whose last index failed, or that were cut short by a restart are indexed again. Unreachable ones wait for the next pass.
- **The real reason on the Repositories page.** A failed repository now shows what failed, for example "git log timed out", with a note that timeouts are retried. It used to say "check the path/URL" whatever the cause. A ready repository says it is checked daily.

#### Fixed
- The daily **retention sweep** (old feedback, audit events, ended sessions, used links) was written but never started with the server, so it only ran from its manual endpoint, although `SECURITY.md` and the operations guide say it runs daily. It now starts with the server.
- A repository stuck on "indexing" after the server was restarted in the middle of an index is picked up by the daily pass after three hours.

#### Upgrade notes
- None. No migration. Both settings have defaults.
