# v0.2.2

## 2026-11-04

### A URL in a comment is no longer a call between repositories

#### Fixed
- **RepoLens was drawn as a caller of an orders service.** The Graph showed a dashed link from `repo_links.py` in RepoLens to the `order_status` route of `demo-orders-service`, because RepoLens's own `joined_urls` function quotes `/api/orders/{order_id}/status` in its docstring to show what it reads. The HTTP detector read that text as a call. It now takes docstrings and comments out of a function before looking for URLs, so only code that builds or uses a URL counts. The links are worked out again on the next index or when the Graph is opened (`DETECTION_VERSION` is now `d8`).

#### Upgrade notes
- None. No migration.

### The sign in screen is now a landing page

#### Changed
- **A real landing page before sign in.** The side panel became a full page: a floating bar (with a full height menu on phones), the headline with the sign in form beside it, a tagline whose words light up one at a time as you scroll, what you can do, how it works in three steps, why you can trust it, eight questions and answers, and a closing call to sign in. It is built to the landing page design rules: Geist type, one spacing and radius scale, flat backgrounds, Phosphor icons, one easing curve, sections that rise into view once, and plain fades for people who ask for less motion. It follows night mode. The copy only states what the code does. No privacy or terms pages exist yet, so there are no links to them.
- **The About, Security and FAQ pages match.** They had kept the old look and their own header and footer. They now use the landing page's floating bar, Geist type, text styles and colours, and one shared footer (Product, Trust, Developers and Community links, and the audit position) that the landing page uses too. Their wording is unchanged.
- **Four more landing sections, with animation.** *How Ask works* (a question, the search, the source check, the cited answer, lighting up in turn along a line), *Repo intelligence* (six capabilities, an animated bar chart of the seven change risk signals and a blast radius that ripples outward, both labelled as illustrations), *How you benefit* and *Best practices*. Only transform and opacity move, on the one easing curve, and people who ask for less motion get the finished picture without movement.
- The page title, description and sharing tags in `index.html` now describe the product.

#### Fixed
- **Footer links to a section did nothing.** "Where each control stands", "Report a vulnerability" and "Official channels" opened the Security page but stayed at the top, because the router does not scroll to a `#section`. The public pages now scroll to it.

#### Added
- Packages `@phosphor-icons/react` (MIT) and `@fontsource-variable/geist` (OFL), bundled with the app, so nothing is loaded from a CDN. Only the landing page uses them.

#### Upgrade notes

### A fresher, cleaner interface

#### Changed
- **Light, grouped sidebar.** The dark block is now a quiet light sidebar with the pages in four groups (Work, Knowledge, Sources, Monitor), a soft tint on the page you are on, and a distinct icon for each page. It follows night mode.
- **One corner-radius scale and flat cards.** Chips, controls, cards and pills now use one set of radii, and cards have a border but no shadow.
- **No cards inside cards.** The Dashboard's four numbers are one strip, the Getting started steps are a list, and findings, components and flows on the Agent personas page are divided lists or tinted blocks. An empty state is a tinted block instead of a dashed box.
- **Fewer badges.** "ready", "done", "private" and "Connected" are no longer shown on every row; a badge now appears only when something needs attention (failed, needs work, shared, high severity). Repository rows show an icon, the name and "N files, updated X" instead.
- **Real icons.** Cards get a lucide icon beside their title, the Repository Explorer rows have an icon, and the text characters ✓, ✗ and ▾ became icons. Disconnect buttons are outlined instead of solid red.
- **Repository Explorer.** The first repository opens by itself, and the search box has a clear scope choice (all repositories, or the open one) and a fixed Search button.
- **Graph colours.** One calm palette for nodes and links (no magenta or orange), links between repositories drawn dashed in the brand colour, quieter repository outlines, repository nodes labelled with distinguishing initials (DC, DO, DS), and a legend in two short rows with the details on hover.

#### Upgrade notes
- None. The conventions are in `CONTRIBUTING.md` under "UI conventions".

### Buttons no longer wrap, and the PostgreSQL test run no longer hangs

#### Fixed

- One of the new persona tests kept a database transaction open while the API updated the same repository row, which hung the PostgreSQL run of the backend tests in CI until GitHub cancelled it after six hours. The test now ends its transaction first. SQLite never showed it.

#### Upgrade notes

### Every persona can describe the repository, not only review it

#### Added
- Agent personas: a second choice next to the usual review, in each persona's own terms. The **Architect** writes a design overview (HLD and LLD), the **Security auditor** a threat model, the **Test engineer** a test plan and the **Developer** a code walkthrough. It describes the repository (or the part you name; an empty box means all of it): two documents, the components and flows with the files they come from, a Mermaid diagram shown as text to copy, and a list of what it could not tell from the code. It reads the matching files and the repository's main files. Every component and flow must name a file it was shown, and anything that does not is dropped; the diagram is kept only if it is a plain flowchart, and when it is left out the page says why. The model is asked for plain sections instead of JSON, which broke on long text. No new table.

#### Changed
- A persona request that matches no code (for example "Explain the HLD and LLD") no longer stops with "No code matched". The persona reads the repository's main files instead, and the review says so.

#### Upgrade notes
- None. `GET /api/personas` now returns each persona's `modes`, and `POST /api/personas/runs` takes an optional `mode` (`review` or `design`).

### Start it with one command, and a much smaller `run-local.sh`

#### Added
- `docker-compose.release.yml` runs RepoLens from the published images (`ghcr.io/gnsaddy/repolens-api` and `repolens-web`), so a user needs only Docker: download the file and `docker compose -f docker-compose.release.yml up -d`. `REPOLENS_VERSION` picks the release. A test checks that it names the images this repository publishes, at this version.
- A **Quick start** section at the top of the README's run instructions.

#### Changed
- How a version is made is now written down (`CONTRIBUTING.md`, `docs/operations.md`): work happens on a branch named after the version (`0.2.2`), a pull request into `main` runs CI, merging it runs CI on `main`, and the CD workflow then publishes the images at that version. A new version is a new branch. `main` is now protected: a pull request merges only after the `backend`, `frontend`, `browser tests` and `images` checks pass and the branch is up to date, for maintainers too.
- Images are now published for every commit on `main` whose CI run passed, not only on a version tag, tagged with the app's own version (`0.2.2` until the number changes), so `docker-compose.release.yml` always pulls the latest passing build of the current version. The CD run starts when CI finishes and does nothing if CI failed or the run came from a pull request. A pushed tag, or a manual run, publishes only if CI already passed for that commit, and a tag must match the app version. A push to `main` never deploys to a cluster; that still needs a tag and `DEPLOY_MODE=kubectl`. Because the tag is reused, the images of a version change under it until the next version is chosen; pin by digest if that matters.
- `run-local.sh` is about 130 lines instead of 280 and does four things: start (`./run-local.sh`), `stop` (`--purge` also deletes local data), `test`, and `docker`. The options `--lan`, `--postgres`, `--llm` and `--reload` and the virtualenv fallbacks are gone. Set `API_PORT` and `WEB_PORT` in the environment for other ports; set `REPOLENS_DATABASE_URL` to use PostgreSQL. `make run` now starts it on SQLite.

#### Upgrade notes
- Anyone who used `./run-local.sh up --postgres` or `--lan` should set `REPOLENS_DATABASE_URL` themselves, or use `docker compose up`. `./run-local.sh up` still works.

### Sign in with GitHub

#### Added
- **Sign in with GitHub.** A **Continue with GitHub** button on the sign-in page, once the server has a GitHub OAuth app. People who already have an account sign in with it: a **verified** GitHub e-mail address must match their account, which is then linked, and its password keeps working. Nothing is created for people with no account, and nobody becomes an admin this way. Under **Settings, Integrations, Sign in with GitHub** an admin can switch it off for the workspace or, optionally, list e-mail domains whose people get an account created on first sign-in. It asks GitHub only for the `user:email` permission, so it sees no repository. New table `github_login_configs` (migration 0034); new settings `REPOLENS_GITHUB_LOGIN_CLIENT_ID` and `REPOLENS_GITHUB_LOGIN_CLIENT_SECRET`.

#### Upgrade notes
- Run the migration (`alembic upgrade head`, 0034). The button stays hidden until you register an OAuth app on GitHub, set the two environment variables and restart.

### Two more personas, more languages and URLs read, old drafts swept

#### Added
- **Two more personas: Architect and Developer.** The Architect reviews structure (wrong-way dependencies, cycles, mixed responsibilities, leaking internals, how much depends on what) and is told which other repositories use the files it read, with the proof. The Developer reviews like a colleague: errors and edge cases not handled, wrong assumptions about other services, leaks, races, callers that would break.
- **Imports are now read for Ruby, PHP, Swift and Scala** (gems from `.gemspec`, PHP namespaces, Swift modules from `Package.swift`, Scala packages), so the Graph covers every common language. Lua, Elixir and Dart files are indexed and listed as not read.
- **URLs added together from pieces are matched to the route they reach:** `"/api/orders/" + id + "/status"` now links to `GET /api/orders/{id}/status`, not to the nearest shorter route.
- **Old drafts and reviews are swept after 180 days** (`REPOLENS_RETENTION_DRAFTS_DAYS`; 0 keeps them).

#### Changed
- `.php`, `.swift`, `.scala`, `.cc`, `.cxx`, `.hpp`, `.hh`, `.lua`, `.ex`, `.exs` and `.dart` files are now indexed (as text); they were skipped before, so C++ headers ending in `.hpp` and `.hh` could not be read either.

#### Upgrade notes
- Re-index repositories that contain PHP, Swift, Scala, Ruby or C++ headers with the newer extensions to pick up their imports. No migration.
