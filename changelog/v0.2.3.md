# v0.2.3

## 2026-11-11

### A failed CI run starts an investigation by itself

#### Added
- **Automations.** On the new **Agent** page (sidebar, Work group, admins) an admin can let RepoLens investigate a failed GitHub Actions run without anyone pasting the log. It reads the log of each failed job (at most three), starts one investigation per failing test or error (at most three a run), and marks them **automatic** in the Investigations list. It is off until turned on, for every repository or for one, with a daily limit (default 5) and an option to include branches other than the repository's own. It only drafts: nothing is posted or changed on GitHub by itself. It runs as the admin who switched it on, stops if that person is no longer an admin, and every start is in the audit log. The page also lists the 30 most recent runs with their outcome and reason. New tables `agent_rules` and `agent_runs` and a column `investigations.source` (migration 0035).

- **The agent reviews new pull requests, and says which model it used.** On the Agent page a second switch (per repository or for all, with its own daily limit) has the Developer and the Security auditor review each newly opened pull request (also reopened, or taken out of draft): they read the changed files as the pull request has them, at most ten, and look at the lines the diff changed. A finding is kept only if it quotes real code. The reviews appear on Agent personas, nothing is posted on the pull request unless an admin approves a draft, and without a language model the run is recorded as skipped. Every run says whether its text was **AI written** (with the model names, from the call log) or **evidence only**. The Agent personas page opens a review from a link (`/personas?run=ID`). The page says to restart the backend instead of crashing if the server is older than the page. Migration 0036 adds `agent_runs.detail`.

#### Added
- **Controls for the agent.** On the Agent page: **pause** it (nothing starts by itself; an admin's own runs still go ahead), give it a **daily token budget** counted from the model call log, **cancel** a run that is going on, and open **Why it ran, and what it did** on each run (the event, the rule that matched, the limits, what it read). Each run shows the tokens it used. Migration 0039.
- **More things that start the agent.** A page that describes changed code gets a drafted update in the wiki proposals after an index; a failed CI run on a pull request leaves a draft comment that is filled in when the investigation finishes; and a nightly watch lists pages that have been out of date for over 14 days (no model). Each has its own switch.
- **Retries when GitHub is down, and health.** A run that fails because GitHub was unreachable, rate limiting or erroring is tried again after 1, 5 and 15 minutes (`REPOLENS_AUTOMATION_RETRY_DELAYS`); a refusal is not. Runs that never finished are marked failed. Insights, RepoLens health, lists the agent's failed and stuck runs and a used up budget.
- **Investigations can look further (opt in).** An admin can switch on **Let investigations look further** under Settings, AI and search. The model then chooses up to five more read only looks at the code (search with other words, open a file, find who calls a function), within ten added chunks and 45 seconds, using the light model tier. What it finds goes through the same ranking and citation check, the timeline shows an **explore** step and the evidence keeps each look and its reason. It cannot run or change anything, and refuses paths with `..`, absolute paths and drive letters. Migration 0038.
- **The agent's Inbox, and approved comments.** Each reviewed pull request leaves a draft comment (the two reviews, saying which model wrote them) and each CI failure a line pointing at its investigations. An admin can read and edit the comment and post it on the pull request after a confirmation; it is posted with the workspace's GitHub connection (write access to pull requests needed), with a closing line saying an AI wrote it and a person approved it, and is in the audit log. This is the only way the agent writes to GitHub. Migration 0037.
- **Try again, run anyway, review again.** A failed run can be tried again, a skipped one run anyway, and a reviewed pull request reviewed again; a specialist whose model answers with something unusable is tried once more by itself, and a failed review shows why.
- **Review new commits too**: an option on the pull request rule (at most five reviews of one pull request).

#### Fixed
- **Switching a model toggle could turn the model off.** Savings mode, the independent review and the new explorer switch created a blank model setting when the workspace had none, and a blank setting means the offline provider. The setting is now created from the model the workspace was using.
- **A model that thinks before it answers could return nothing.** When a reply came back empty because the thinking used the whole output budget (for example Gemini on a pull request review, which then failed with "Expecting value"), the same model is now asked again with more room, up to 16,000 tokens.
- **A CI log with no failing test is read where the error is.** The automatic investigation used the last 6,000 characters of the log, which on GitHub are the artifact upload and clean up steps after the failure. It now uses the lines before GitHub's first `##[error]` mark and the marks themselves, else the lines around the first one that mentions a failure, and drops the time stamps.

#### Upgrade notes
- Run the migrations (`alembic upgrade head`, 0035 to 0039). For pull request reviews also tick **Pull requests** in the repository's webhook. To use it, tick **Workflow runs** in the repository's GitHub webhook (the one pointing at `/api/webhooks/github`) and make sure `REPOLENS_GITHUB_WEBHOOK_SECRET` is set. Nothing changes until an admin turns a rule on.
