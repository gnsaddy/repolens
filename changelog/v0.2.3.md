# v0.2.3

## 2026-11-11

### A failed CI run starts an investigation by itself

#### Added
- **Automations.** Under **Settings, Automation** an admin can let RepoLens investigate a failed GitHub Actions run without anyone pasting the log. It reads the log of each failed job (at most three), starts one investigation per failing test or error (at most three a run), and marks them **automatic** in the Investigations list. It is off until turned on, for every repository or for one, with a daily limit (default 5) and an option to include branches other than the repository's own. It only drafts: nothing is posted or changed on GitHub. It runs as the admin who switched it on, stops if that person is no longer an admin, and every start is in the audit log. The page also lists the 30 most recent runs with their outcome and reason. New tables `agent_rules` and `agent_runs` and a column `investigations.source` (migration 0035).

#### Upgrade notes
- Run the migration (`alembic upgrade head`, 0035). To use it, tick **Workflow runs** in the repository's GitHub webhook (the one pointing at `/api/webhooks/github`) and make sure `REPOLENS_GITHUB_WEBHOOK_SECRET` is set. Nothing changes until an admin turns a rule on.
