# v0.2.3

## 2026-11-11

### A failed CI run starts an investigation by itself

#### Added
- **Automations.** On the new **Agent** page (sidebar, Work group, admins) an admin can let RepoLens investigate a failed GitHub Actions run without anyone pasting the log. It reads the log of each failed job (at most three), starts one investigation per failing test or error (at most three a run), and marks them **automatic** in the Investigations list. It is off until turned on, for every repository or for one, with a daily limit (default 5) and an option to include branches other than the repository's own. It only drafts: nothing is posted or changed on GitHub. It runs as the admin who switched it on, stops if that person is no longer an admin, and every start is in the audit log. The page also lists the 30 most recent runs with their outcome and reason. New tables `agent_rules` and `agent_runs` and a column `investigations.source` (migration 0035).

- **The agent reviews new pull requests, and says which model it used.** On the Agent page a second switch (per repository or for all, with its own daily limit) has the Developer and the Security auditor review each newly opened pull request (also reopened, or taken out of draft): they read the changed files as the pull request has them, at most ten, and look at the lines the diff changed. A finding is kept only if it quotes real code. The reviews appear on Agent personas, nothing is posted on the pull request, and without a language model the run is recorded as skipped. Every run says whether its text was **AI written** (with the model names, from the call log) or **evidence only**. The Agent personas page opens a review from a link (`/personas?run=ID`). The page says to restart the backend instead of crashing if the server is older than the page. Migration 0036 adds `agent_runs.detail`.

#### Fixed
- **A CI log with no failing test is read where the error is.** The automatic investigation used the last 6,000 characters of the log, which on GitHub are the artifact upload and clean up steps after the failure. It now uses the lines before GitHub's first `##[error]` mark and the marks themselves, else the lines around the first one that mentions a failure, and drops the time stamps.

#### Upgrade notes
- Run the migrations (`alembic upgrade head`, 0035 and 0036). For pull request reviews also tick **Pull requests** in the repository's webhook. To use it, tick **Workflow runs** in the repository's GitHub webhook (the one pointing at `/api/webhooks/github`) and make sure `REPOLENS_GITHUB_WEBHOOK_SECRET` is set. Nothing changes until an admin turns a rule on.
