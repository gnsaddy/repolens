### Answers check that their sources cover the question, and flag names that do not exist

#### Added
- **A second search when the first one misses the question.** The best sources must mention the question's key words (stemmed, split on underscores). Below 60% coverage RepoLens searches once more, wider and with the missing words in other forms, and keeps whichever pass covers more. No model is called, so the same question always gets the same sources. The response carries `retrieval` (coverage, missing words, whether it searched again). If the sources still cover less than half, the chat and the Knowledge page say "Your sources do not mention: …".
- **Names that do not exist.** After the model answers, the file paths, routes and functions it names outside code blocks are looked up in the sources, the question and the indexed repositories you can see. A name found nowhere is reported (`unsupported_names`, an amber **Check these names** badge in the chat, a line on the Knowledge page). It is a flag, not a block. Build requests are skipped, because they create new names on purpose. New `services/name_check.py`.

#### Changed
- The Ask chat now uses the same retrieval function as the Knowledge page, the Wiki, MCP and the quality runs (`knowledge.retrieve_checked`), so a retrieval check tests what the chat actually uses. Before, the chat had its own copy of the search and route steps.
- The answer-memory `PIPELINE` moves from `p3` to `p4`, so saved answers without these fields are not replayed.

#### Fixed
- Asking the same question fresh a second time failed with "The AI model could not answer … cache_entries.key", because the saved answer was inserted again under the same key. A fresh answer now replaces the saved one. Full quality runs always ask fresh, so repeating a full run hit this.

#### Upgrade notes
- None. No re-index needed.

### Skills: guidance the model follows, approved by an admin

#### Added
- **Settings → Skills**: members submit a skill (or upload a `SKILL.md`), admins approve, reject, turn off, edit or delete; an admin's own skills are active at once. Private to the workspace. Saved answers are keyed on the guidance used, so a new or changed skill is never answered from stale memory.

### Indexing no longer slows down disproportionately on big repositories

#### Fixed
- Building the knowledge graph resolved every import by scanning every file path in the repository, so indexing time grew with files x imports x files. ### RCA reports follow a debugging discipline

## 2026-10-25

### Refusing weak document matches: measured, not shipped

#### Changed
- The document evaluation suite now measures what refusing weak matches would do ("the documents do not cover this") at two thresholds.

#### Findings
- Refusing when fewer than a quarter of the question's words appear in the best passages catches 88% of questions the documents cannot answer, but wrongly refuses 58% of valid re-worded questions (31% of all valid questions). With the local embedder, re-worded questions find their page through vectors and share few words with it, so a word-coverage rule cannot tell them from uncovered ones.
- No change was made to answering. The model is still told to say when the sources do not cover a question, and a cheap model's answer that neither cites nor says so is retried on a stronger one.
- Revisit when an embedding model is connected: its raw similarity score should separate the two cases, and the suite will show whether it does.

### MCP server and personal access tokens

#### Added
- **MCP server** at `/api/mcp` (Model Context Protocol over HTTP, JSON-RPC 2.0): an editor or agent such as Claude Code or Cursor can `search` code, documents and pull requests, `ask` with cited sources, `find_symbol` and `symbol_brief` before changing code, `read_wiki_page`, `who_to_ask`, `change_risk`, `get_investigation`, and (with a write token) `investigate`.
